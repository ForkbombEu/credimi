# FCAF taxonomy

Canonical wallet-solution / relying-party category and subgroup vocabulary.

## Identifier grammar

Test identifiers encode their owning FCAF section and subsection:

```text
WS_RP_<CATEGORY>_<SUBGROUP>_<specifics>_<NNN>
```

Examples:

- `WS_RP_DM_AddressData_Emailaddress_PID_IETF-sd-jwt-vc_001`
- `WS_RP_IA_MainInteraction__003`

`suite.section` in test YAML is not reliable: some entries carry a semantic
dotted path (`data_model.address_data`) while others carry ARF clause
references (`"6.1"`, `"3"`). The identifier prefix is the source of truth for
grouping reports and catalogs.

## Source of truth

Edit [`taxonomy.json`](./taxonomy.json) only. Then regenerate:

```sh
go run ./cmd/fcaf-taxonomy-gen
```

(or `go generate ./pkg/...` via `pkg/gen.go`).

That writes:

- `taxonomy_data.generated.go` (committed with this package)
- `webapp/src/lib/fcaf/taxonomy.generated.ts` (gitignored; regenerated by
  `bun run generate:fcaf-taxonomy` / `generate:definitions`)

Colour tokens stay in language adapters (`reportpdf` RGB, webapp Tailwind
classes). Do not put colours in `taxonomy.json`.

## Parse helpers

`Parse` / `parseFCAFTestId` are hand-written in Go and TypeScript. Shared
golden cases in [`testdata/parse_cases.json`](./testdata/parse_cases.json) keep
them aligned.
